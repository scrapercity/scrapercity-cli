BASE: https://app.scrapercity.com
AUTH: Authorization: Bearer <api_key>
ALL RESPONSES: JSON
PATTERN: POST start → GET status → GET download

PRICING: Plans $49, $149, $649/mo. Each gives wallet credits. Scrapers deduct per-lead.

apollo
  Body: { url: "https://app.apollo.io/#/people?...", count: 1000, fileName: "My Export" }
  Returns: { runId, message, lead_database? }
    lead_database (when there are matches): { matches, url, api } - leads with the same
    filters already in the Lead Database (ones you don't have), a dashboard link, and the
    /api/v1/database/leads call that returns them now.
  Cost: $0.0039/lead | Min 500, max 50000
  DELIVERY: UP TO 4 DAYS. Use webhook, not polling.
  To filter by title/location/industry without a URL, use the Lead Database (below).

maps
  Body: { searchStringsArray: ["plumbers"], locationQuery: "Denver, CO", maxCrawledPlacesPerSearch: 500 }
  Returns: { runId, datasetId, priceMicro, local_business_database? }
    local_business_database (when there are matches): { matches, url, api } - businesses for the
    same search already in the Local Business Database (ones you don't have), a dashboard link,
    and the /api/v1/database/local-businesses call that returns them now.
  Cost: $0.01/place | Delivery: 5-30 min
  To search by category and location without running a scrape, use the Local Business Database (below).

────────────────────────────────────────
STATUS & DOWNLOAD
────────────────────────────────────────

GET /api/v1/scrape/status/{runId}
  Returns: { status, statusMessage, handled, requested, outputUrl }
  Status values: RUNNING | SUCCEEDED | FAILED | CANCELLED
  When SUCCEEDED: outputUrl = "/api/downloads/{runId}"

GET /api/downloads/{runId}
  Returns: CSV file (binary stream)
  Only available when status = SUCCEEDED

POST /api/v1/scrape/cancel/{runId}
  Cancel a running job.

GET /api/v1/scrape/logs/{runId}
  View run logs.

DATABASES (GET, $149/mo plan and up, 100k new records/day)
────────────────────────────────────────

GET /api/v1/database/leads?title=CTO&country=United States&hasEmail=true&page=1&limit=100
  Filters: title, industry, country, state, city, companyName, companyDomain,
           seniority, department, hasEmail, hasPhone, minEmployees, maxEmployees, socialUrl
  Company filters: keywords (company tags, whole-word, any match), revenueMin, revenueMax (USD),
           companyCountry, companyState, companyCity (company HQ, not the person)
  Exclusions: notTitle, notKeywords, notIndustry
  url=<people-search URL>: use that search's filters (other params override).
           The response adds search_translation: { applied, approximated, not_supported }.
           A URL with no filters the database can use returns 400.
  POST /api/v1/database/leads with a JSON body takes the same parameters (arrays as JSON
           arrays). Use it for a long url or long lists: a query string over ~16KB is refused.
  Country: full name ("United States"); US, USA, UK, UAE also work.
  Array params use repeated keys: ?seniority=vp&seniority=director
  (keywords / notKeywords also accept commas: ?keywords=saas,fintech)
  Optional:
    excludeDelivered=true  skip leads this account already has (from the API or the
                           dashboard). For daily pulls. Keep page=1 (or use after).
    after=<id>             cursor paging in id order. Send after=0 first, then
                           pagination.next_after from each response until it is null.
  Every lead returned is saved to your account. Only NEW leads count toward the
  100k/day limit; fetching a lead you already have again is free.
  Returns: { data: [...leads], pagination: { page, limit, total, totalPages, has_more, next_after }, rate_limit,
             search_translation? }
  Lead fields include company_industry, company_size, employees_count, company_website,
  company_annual_revenue, company_city, company_state, company_country, keywords.
  409 with filters_not_applied_yet: the company filters listed can't be used yet (company
  data still being prepared right after launch). Nothing is returned or counted; retry later
  or drop those filters.
  503: the search took too long to run. Narrow it (fewer titles or keywords, add a location
  or company size) and retry.

GET /api/v1/database/local-businesses?category=Dentist&country=US&hasContact=true&limit=100
  Local businesses ($149/mo plan and up, 100k new businesses/day), same pattern as above.
  Search the way you would on Google Maps:
  keyword=thai restaurant (repeat for several; matches business names and categories, any keyword;
           a place inside a keyword, "plumbers in Austin TX", is the location when none is sent)
  location=Houston TX (repeat for several, up to 2,000: cities, states, countries or postal codes)
           The response adds searched_as: { keywords: [{ text, words, categories, matches_nothing }],
           places: [{ text, read_as, kind, not_found? }] }. A search that finds nothing adds
           lead_database: { count, read_as, filters, dashboard_url } when the Lead Database has 100+
           people for it (keywords read as job title or company keywords, whichever has more).
  Filters: category (repeat for several), country (two-letter code), state, city, postalCode,
  query (business name and description), title (business name, comma separated for several),
  minRating, maxRating, minReviews, maxReviews,
  hasEmail, hasPhone, hasWebsite, hasContact (only businesses with a named contact person).
  box=minLat,minLng,maxLat,maxLng: only businesses inside that map area (a box that can't be
           read returns 400).
  Exclusions: notCategory (repeat for several)
  url=<Google Maps search URL>: use that search's keyword and place (other params override).
           The response adds search_translation: { applied, approximated, not_supported }.
           A URL with nothing the database can use returns 400.
  POST /api/v1/database/local-businesses with a JSON body takes the same parameters (arrays as
           JSON arrays). Use it for a long url or long lists: a query string over ~16KB is refused.
  Optional: excludeDelivered=true, after=<id> (as above).
  Returns: { data: [...businesses], pagination: { page, limit, total, totalPages, has_more, next_after },
             rate_limit, search_translation?, searched_as?, lead_database? }
  Business fields include title, category_name, address, city, state, postal_code, country_code,
  phone, website, emails, total_score, reviews_count, lat, lng, and contact_first_name,
  contact_last_name, contact_job_title, contact_email, contact_mobile when there is a named contact.
  503: the search took too long to run. Narrow it (add a category, a city, a state or a postal
  code) and retry.

GET /api/v1/database/ecommerce?...
  Same pattern (including excludeDelivered and after), different dataset.

────────────────────────────────────────
ERROR CODES
────────────────────────────────────────
401 = Invalid/missing API key
402 = Insufficient balance (check wallet first!)
403 = Account cancelled or charge processing
409 = Duplicate request (same search within 2 min)
429 = Rate limited / duplicate within 30s
503 = Service temporarily unavailable

────────────────────────────────────────
WORKFLOW EXAMPLES
────────────────────────────────────────

1. MAPS SCRAPE (fast):
   POST /api/v1/scrape/maps → get runId → poll status every 15s → download CSV

2. APOLLO SCRAPE (slow):
   POST /api/v1/scrape/apollo → get runId → configure webhook → wait for callback
   Do NOT poll Apollo in a tight loop. Check once per hour at most.

3. ENRICH PIPELINE:
   Apollo/Maps → download CSV → extract emails → POST email-validator → download validated CSV

4. LEAD DATABASE (instant):
   GET /api/v1/database/leads?title=CTO&industry=computer+software&hasEmail=true&page=1
   Loop pages until page > totalPages

5. LOCAL BUSINESS PIPELINE:
   Yelp/Angi/Maps → download CSV → POST email-finder with names+domains → POST mobile-finder

6. REAL ESTATE PIPELINE:
   Zillow Agents + Property Lookup → download CSVs → enrich with email-finder

7. LOCAL BUSINESS DATABASE (instant):
   GET /api/v1/database/local-businesses?keyword=dentist&location=Austin%2C+TX&hasEmail=true&page=1
   Loop pages until page > totalPages
